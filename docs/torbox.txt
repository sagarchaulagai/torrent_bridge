Main API
Full documentation for TorBox

Current API Base: https://api.torbox.app

Current API Version: v1

You can find more API docs here: http://api.torbox.app/docs (they aren't as great as these, but is in a format most people would be familiar to).
General Information

    You can rely on both success booleans or status codes to determine if a call was a success. Status code 200 always means a success. 403 means authentication error. 500 means something went wrong on TorBox's end. 400 means the user did something wrong, or an input wasn't correct, or expected.

    There will always be a user-friendly message in detail for a reason why a call was a failure, or a success message. You may forward these directly to users.

    The /usenet and the /webdl API endpoints are nearly the same as the /torrents API endpoints apart from some different named inputs and outputs.

    All outputs are JSON unless otherwise specified. Check out the examples to be sure.

Rate Limits

    Unless stated below, all endpoints are rate limited to 300/min per API token, no edge rate limiting.

    POST /torrents/createtorrent is rate limited to 60/hour for uncached items per API token, 300/min if the items are cached. Please read the documentation for more information.

    POST /usenet/createusenetdownload is rate limited to 60/hour per API token.

    POST /webdl/createwebdownload is rate limited to 60/hour per API token.

    We no longer accept IP whitelisting requests due to rate limiting being API token based, rather than IP based.

Standard Response

Below is the standard JSON response that most requests will return. In short, always use the "success" key to determine if a request was successful or not, "error" to determine the exact error reason, "detail" as a user-friendly message whether success or error, and data contains the response information you are looking for.
View More
json

{
    "success": boolean, // whether a response is successful or not
    "error": string, // an error code if there was an error, or null if success
    "detail": string, // a user-friendly message
    "data": any // usually an object/dict, but can be anything, check the examples
}

Dates

All dates returned from the API are normalized to UTC time. All dates are in the format:

%Y-%m-%dT%H:%M:%SZ

Example: 2024-10-21T20:47:03Z = The 21st of October, 2024 at 8:47:03 PM UTC.

This makes it easy for users and integrations to parse these dates and change them to the user's time zone for better UX. For more information on these formats, you can take a look at this cheat sheet.

POSTCreate Torrent
https://api.torbox.app/v1/api/torrents/createtorrent
Overview

Creates a torrent under your account. Simply send either a magnet link, or a torrent file. Once they have been checked, they will begin downloading assuming your account has available active download slots, and they aren't too large.
Rate Limits

This endpoint has two limits that apply at the same time:

    300 requests per minute: a shared ceiling that every request counts against, whether the torrent is cached or uncached.

    60 uncached torrents per hour: an additional, stricter limit that only uncached torrents count against.

The important thing is that cached and uncached requests both draw from the same 300/min pool, but uncached requests also draw from their own separate 60/hour pool. An uncached request therefore counts twice: once against the per-minute limit, and once against the per-hour uncached limit.

Example: In a single minute you add 250 cached + 50 uncached torrents. That's 300 total, so you've hit the per-minute limit for that minute. But those 50 uncached torrents also came out of your 60/hour uncached budget, leaving only 10 uncached torrents for the remaining 59 minutes of that hour. (You could still add plenty more cached torrents during that hour, since cached requests aren't capped hourly: only by the 300/min ceiling.)

Requires an API key using the Authorization Bearer Header.

Overview

Takes in a list of comma separated torrent hashes and checks if the torrent is cached. This endpoint only gets a max of around 100 at a time, due to http limits in queries. If you want to do more, you can simply do more hash queries. Such as:

GETRequest Download Link
https://api.torbox.app/v1/api/usenet/requestdl?token=&usenet_id=&file_id=&zip_link=&user_ip=&redirect=&append_name=
Overview

Requests the download link from the server. Because downloads are metered, TorBox cannot afford to allow free access to the links directly. This endpoint opens the link for 3 hours for downloads. Once a download is started, the user has nearly unlilimited time to download the file. The 1 hour time limit is simply for starting downloads. This prevents long term link sharing.
Permalinks

Instead of generating many CDN urls by requesting this endpoint, you can instead create a permalink such as: https://api.torbox.app/v1/api/torrents/requestdl?token=APIKEY&torrent_id=NUMBER&file_id=NUMBER&redirect=true and when a user clicks on it, it will automatically redirect them to the CDN link. This saves requests and doesn't abuse the API. Use this method rather than saving CDN links as they are not permanent. To invalidate these permalinks, simply reset your API token or delete the item from your dashboard.
Authorization

Requires an API key as a parameter for the token parameter.
AUTHORIZATIONBearer Token
This request is using Bearer Token from collectionMain API
PARAMS
token

Your API Key
usenet_id

The usenet download's ID that you want to download
file_id

The files's ID that you want to download. Optional if using "zip_link".
zip_link

If you want a zip link. Required if no file_id. Takes precedence over file_id if both are given.
user_ip

The user's IPv4 to determine the closest CDN. Optional.
redirect

If you want to redirect the user to the CDN link. This is useful for creating permalinks so that you can just make this request URL the link.
append_name

If you want to add the "filename" parameter to the returned CDN link. Optional. Default false.

Stream
Overview

With the release of TorBox v8.1 we are introducing the ability to stream any video file directly in your browser, and this is fully powered by our API, which is available for developers to integrate into their apps. With minimal wait times for stream starts, low bandwidth streaming, and integrated subtitles and audio choosing, this API makes it simple to create a web player based off of a user's TorBox video files.
Authorization

For all requests, you will need your API token which can be found on your TorBox settings page under the API key section. Simply copy or refresh the API token and use it in the API.

GETCreate Stream
https://api.torbox.app/v1/api/stream/createstream?id=&file_id=0&type=torrent&chosen_subtitle_index=&chosen_audio_index=0&chosen_resolution_index
Overview

Creates a new stream based off of the data provided.
Selecting Subtitles and Audios

We use indexes to determine which audio and subtitle you would like to select. To view all available indexes, you must request this endpoint intially with "null" or 0, for the chosen indexes. This will return a metadata dictionary in the response, which will contain the list of audios and subtitles available for this stream. When choosing a subtitle or audio stream, use the relative index, starting from 0, rather than the "index" value. This is important for selecting the correct index. Once your user gets a selection of audios and subtitles available, you can submit this to the endpoint again to get the chosen stream.

    null - Selecting no subtitle. Not available for audio as one must always be selected.

    0 - Selecting first subtitle or audio

Selecting Resolution

Similar to the subtitles and audios, we use indexes to determine the resolution chosen. Unlike the above, these are predetermined. We do not upscale video, so if for example, you pass a 1080p video, and request it with resolution, 7, it will stay at 1080p. Please see the below for options.

    null - Original video resolution. No downscaling will take place.

    0 - 144p

    1 - 240p

    2 - 360p

    3 - 480p

    4 - 720p

    5 - 1080p

    6 - 1440p

    7 - 2160p

Types

This endpoint allows you to handle torrents, usenet and web downloads all in one. This is why the "type" parameter is available. It defaults to "torrent".

    torrent - Torrents

    usenet - Usenet downloads

    webdownload - Web Downloads

Important Notes

    Only text based subtitles are supported. If a non-text based subtitle is selected, it will be ignored.

    If a subtitle or audio index does not exist on the stream, it will be ignored.

    There are a lot of edge-case videos, if something doesn't work, don't hesitate to report the download hash and file_id of the failing video file.

    This is a Pro only feature.
